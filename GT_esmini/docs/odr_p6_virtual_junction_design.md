## 1. Summary

Native OpenDRIVE virtual-junction (VJ) support implemented in-place in core esmini files. The map is never transformed: the main road stays unsplit, all road ids/s-coordinates are preserved, and the runtime learns mid-road connections directly. Design principle: **"straight-through is free, turning is the feature"** — every change is an additive branch that activates only when (a) a VJ anchor lies inside a motion step AND a turn is selected, (b) a route/path crosses a virtual connection, or (c) membership/OSI queries hit the main-road span. All parse follows the DIRECT-junction precedent template (typed parse → post-parse synthesis → targeted RoadPath/MoveToConnectingRoad special cases → IsOsiIntersection=false → direct-style OSI lane pairing).

Every core edit is `[GT_ODR:vj-*]`-marked (block form `[..-begin]/[..-end]` for hunks >15 ln), manifest-recorded with per-file upstream blob-SHA baselines, **dual-homed** for cpp (pristine RoadManager.cpp = git-merge/PR vehicle; GT_RoadManager.cpp fork = build-effective) with an explicit **OVERLAP-RESIDUAL** accounting category where fork-only patches ([GT_LHT], [GT_ODR:junc-abort/junc-crossing]) intersect vj hunks. Written PR-quality against pristine FIRST with zero gt_esmini includes. 8 stages; PR packaging (4 slices to upstream `dev`, issue #592 first) trails runtime. Total ~31-43 dev-days ≈ 7-9 calendar weeks (runtime-complete S0-S7b: ~5-7 weeks). Behavioral invariance on all non-virtual assets is a hard gate at every stage, measured by a real value-level oracle: NEW RM-layer **motion-traversal goldens** + per-scenario **telemetry tolerance goldens** captured at the v3.4.0 baseline and diffed at every stage.
