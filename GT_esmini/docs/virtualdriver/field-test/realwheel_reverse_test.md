# 実機テスト（逆構成）— ハンドル=AI / ペダル=あなた

**所要**: 5分
**やること**: ペダルだけ操作する。カーブの途中で止める。前輪の向きを見る。

---

## 0. 異常時にどうするか（最初に読む）

**今回はハンドルに力が出ます。** 前回とここが決定的に違います。

### ハンドルをしっかり回すと、操舵があなたに切り替わることがあります（オーバーライド）

手順7で最後に試します。**AI の操舵に軽く手を添えるだけなら何も起きません。**
しっかり抵抗する・切り込むと「人が割り込んだ」と判定され、その瞬間から
**ハンドルはあなたの操作どおりに動きます**（AI の操舵はそこで止まります）。
これは異常ではなく、割り込み検出が働いた証拠です。

> **切り替わった後は、ハンドルの Triangle（△）ボタン（G29既定配置・ボタン3、
> config の `auto_resume_button`）を押すと AI の操舵へ戻ります。**
>
> **2026-07-30、実機で確認済みです**（ボタン押下→MANUAL→AUTO復帰→サーボ再
> アクティブ化まで、ユーザー本人がボタンを押して確認。記録は
> [一次記録 §2.2](../measurements/realwheel_handover_results_2026-07.md)）。
>
> **放っておいても（自動タイムアウト）は戻りません。** `auto_return_timeout` を
> 意図的に無効のままにしてあるため、ボタン操作が唯一の手段です。
>
> なお、復帰時のテレメトリ (`override.resume_pressed`) はこの構成では常に
> `false` のまま記録されない既知の欠落があります（機能は動きますが、後から
> ログだけで「ボタン操作が契機だったか」を確認することはできません。6章参照）。
>
> **それでも、手順4〜6（停止時の舵保持テスト）より前には強く回さないでください。**
> オーバーライドさせるとその回はAIの操舵が完全に止まるので、途中で復帰させても
> 「AIが停止時に舵を保持したか」の確認そのものはやり直しになります。オーバーライドと
> 復帰の確認は手順7〜8にまとめてあります。

### ハンドルが自分の意思に反して回り始めたら

1. **手を離してください。** 握って抵抗しないでください。
   （抵抗すると後述の安全装置が働く条件は満たしますが、**その2秒間は力がかかり続けます**。
   手を離すのが一番早くて安全です。）
2. それでも止まらなければ、**ハンドルの USB ケーブルを抜く**か、**電源アダプタを抜いて**ください。
3. ウィンドウを閉じる／`Esc` でも止まります。

### 安全装置について

強い力が **2秒間** 続いたら、走行が自動で終了してハンドルの力が落ちるように
設定してあります（発火するのは実効力 0.570 以上が 2.0 秒継続したとき）。
これは 2026-07-29 にあなたの実機で発火を確認済みの機構です。
**万一ハンドルが目一杯まで振り回されても、2秒で切れます。**

## 1. 「動くのが正常」です — 前回との違い

| | 前回（順構成） | **今回（逆構成）** |
|---|---|---|
| ハンドル | あなたが操作 | **AIが操作（力が出る）** |
| アクセル・ブレーキ | AIが操作 | **あなたが操作** |
| ハンドルが勝手に動いたら | **異常** | **正常** |

今回は **起動した瞬間から、ハンドルが AI の操舵に合わせて動きます。** これは正常です。
カーブに沿って滑らかに回り、カーブが緩めば戻ります。

**あなたはハンドルを握らなくて構いません。** 軽く添えるだけにして、
AI がどう切っているかを感じてください。**軽く添えている間は**ハンドルを回しても
車の進路は変わりません。ただし今回から、**しっかり回して抵抗する（オーバーライド）と、
そこから先はあなたの操作どおりに車が曲がります**（0章参照）。Triangle（△）ボタンで
AI へ戻せます。この試験は手順7〜8で行います。先にやらないでください
（手順4〜6の停止保持テストが済んでからにする理由は0章参照）。

### 正常な動き方 / 異常な動き方

| | 見え方・感じ方 |
|---|---|
| **正常** | カーブに合わせて滑らかに回り、一定の角度で落ち着く。手を添えると軽い抵抗がある |
| **正常（新規・意図的にやったとき）** | しっかり回すと AI ではなく自分の手の動きどおりに切れる（オーバーライド）。Triangle（△）ボタンでAIへ戻せる。手順7〜8でのみ試す |
| **異常** | 目一杯まで一気に振り切れる／小刻みに激しく振動する／止まっているのに回り続ける |

異常だと思ったら **手を離して**、上の「0.」に従ってください。

## 2. 起動

パッケージを展開したフォルダで **PowerShell** を開き、そのまま貼り付けてください。

```powershell
cd <展開先>\GT_Sim_v0.14.1
$env:ELECTRON_RUN_AS_NODE = $null
.\bin\GT_Sim.exe --osc .\resources\xosc\verification\08_handoff\scenario_realwheel_reverse_split.xosc --window 60 60 1280 720
```

`--window 60 60 1280 720` は必ず付けてください。省くとウィンドウが出ないことがあります。
出ない場合は `--window 0 0 1024 600` に変えて再実行してください。

> **`GT_Sim_v0.14.1`**（2026-07-30 未明ビルド、HEAD `e78bde41` 相当）にこのシナリオと
> 設定一式が入っています。展開先はこのバージョン名に読み替えてください。

## 3. 何をするか

車は 30 km/h で走り出します。**ハンドルは触らなくて構いません。**

| # | 操作 | 期待される見え方 |
|---|---|---|
| 1 | 何もしない（5秒ほど見る） | AIがハンドルを回し、車はカーブに沿って車線内を走る |
| 2 | ハンドルに**軽く**触れる（**強く回さない**） | 車の進路は変わらない。AIの操舵をそのまま感じられる（強く回す試験は最後の手順7で） |
| 3 | アクセルを踏む／離す | 速度が変わる。ハンドルはAIが操作し続ける |

> ### ⚠ 速度を出しすぎると曲がりきれません（不具合ではありません）
>
> **35 km/h あたりが限界です。** この道は半径 49 m の右カーブで、AI が
> 車線を保てる速度は横加速度 2.0 m/s²（`max_lateral_accel`）から
> **√(2.0 × 49.1) ≒ 9.9 m/s = 約 36 km/h** と決まります。
>
> | 速度 | 横加速度 | 結果（ヘッドレス実測） |
> |---|---|---|
> | 30 km/h (8.6 m/s) | 1.5 m/s² | 車線内（lane_offset 0.33 m） |
> | 37 km/h (10.3 m/s) | 2.2 m/s² | 車線内 |
> | **53 km/h (14.6 m/s)** | **4.4 m/s²** | **膨らんで車線を外れる** |
>
> **この構成では AI は減速できません。** 速度はあなたの担当なので、
> AI は「曲がりきれない速度で進入した」ときに速度を落とす手段を持ちません。
> 外れたら、これは AI の操舵の不具合ではなく**入りすぎ**です。
> 分担が効いている証拠でもあります（縦が AI なら手前で減速していました）。
> 曲がりきれなかったら、アクセルを緩めてから試し直してください。
| 4 | **カーブの途中でブレーキを踏み、完全に停止する** | **前輪の向きが切れたまま保たれる** |
| 5 | 停止したまま5秒ほど前輪を見る | 向きが変わらない（真っ直ぐに戻らない） |
| 6 | もう一度アクセルを踏む | そのままカーブに沿って走り出し、車線から出ない |
| 7 | **（最後に）ハンドルをしっかり回して抵抗してみる** | **オーバーライドが発火し、そこから先はあなたの操作どおりに車が曲がる**（0章参照） |
| 8 | **Triangle（△）ボタン（G29のボタン3）を押す** | **AIの操舵に戻る。** ハンドルが再びAIの指令に追従して動き始める（サーボ再アクティブ化）。ここまで確認できたら走行を終了してよい |

## 4. 成功はこう見える

**2つを同時に見ています。**

### (A) 逆構成が成立しているか

- **ハンドルを回しても進路が変わらない** ＝ 横はAIが持っている
- **アクセル・ブレーキで速度が変わる** ＝ 縦はあなたが持っている

この2つが同時に成り立てば成立です。**判定は「ハンドルを回しても曲がらない」が
いちばん分かりやすい**です。前回の「手を離せば車線を外れる」と同じで、
二者択一で判別できます。

### (B) 停止時に舵が保持されるか（不具合修正の確認）

**手順4〜5がこのテストの本題です。**

- **成功**: カーブの途中で止めても、**前輪は切れた角度のまま**。真っ直ぐに戻らない。
- **失敗**: 停止すると前輪がいったん真っ直ぐになり、さらに**反対側へ目一杯切れる**。

前輪の向きは**ビューアの画面で見てください**（車を横または後ろから見ると分かりやすい）。
ハンドルの位置でも分かりますが、サーボが効いているので画面で見るほうが確実です。

もうひとつの判別方法として、**手順6の再発進**があります。
舵が保持されていれば、動き出した瞬間からカーブに沿って走ります。
保持されていなければ、動き出した瞬間に反対側へ切れて車線から飛び出します。

> ヘッドレスでは修正後に舵が保持されること、**2026-07-30 に実機（目視）でも保持されること**を
> 確認済みです。数値は
> [一次記録 §2.3](../measurements/realwheel_handover_results_2026-07.md)。

### (C) テレメトリの復路が繋がっているか（driver.steer の確認）

**2026-07-30、実機ログで確認済みです**（値は
[一次記録 §2.4](../measurements/realwheel_handover_results_2026-07.md)）。
再確認したい場合は、別の PowerShell 窓で走行中に次のどちらか一方を実行してください
（**同じ UDP ポート 48202 を使うので同時には実行できません**）。

**方法1: オーバーライドの発火/復帰だけ見る（既存ツール）**

```powershell
DriverScript\.venv\Scripts\python.exe scripts\vd_override_observer.py
```

起動直後は `AUTO` と出ます。手順7でオーバーライドを発火させたら
`MANUAL (lat)` に変わることを確認してください。

**方法2: driver.steer の値そのものを見る**

```powershell
@'
import socket, struct, json
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("127.0.0.1", 48202))
h = struct.Struct("<iI")
for _ in range(30):
    data, _ = s.recvfrom(65535)
    counter, size = h.unpack_from(data, 0)
    tel = json.loads(data[h.size:h.size + size])
    print(tel.get("sim_time"), tel.get("driver", {}).get("steer"))
'@ | DriverScript\.venv\Scripts\python.exe -
```

**カーブに沿って値が変化していれば直っています。** `0.0` のまま並んだら、
まだ凍ったままです。

> **テレメトリの生JSONを直接読むときの注意**: 存在しないキーを `dict.get(key, 0)` で読むと、
> 無警告で `0` が返り「力が出ていない」ように見えます。正しいキー名は6章の表を参照してください。
> また `ffb.gates.*` は**1フレーム遅れ**です。詳細は
> [一次記録 §3](../measurements/realwheel_handover_results_2026-07.md)。

## 5. 失敗はこう見える

| 見え方 | 意味 | どうする |
|---|---|---|
| ハンドルを回すと車が曲がる | 横があなたに渡っている（分担が逆） | 中止して報告 |
| アクセルを踏んでも速度が変わらない | 縦がAIに渡っている | 中止して報告 |
| 停止すると前輪が真っ直ぐ／反対に切れる | **停止時の不具合が残っている** | 中止して報告 |
| 手順7でしっかり回してもハンドルの動きが変わらない | **復路が繋がっていない** | 報告（危険ではない） |
| 手順8でTriangleボタンを押してもAIの操舵に戻らない | **復帰経路が効いていない** | 報告（危険ではない） |
| ボタンを押していないのに AI の操舵に戻った | 想定外の動き（`auto_return_timeout=0` のため起こらないはず） | 報告（危険ではない） |
| ハンドルが目一杯まで振り切れる／激しく振動する | **危険。安全装置が2秒で切るはず** | **手を離す→USB/電源** |
| 車が最初から動かない | ペダルが認識されていない可能性 | 起動時ログに `G29` の行があるか確認 |
| ウィンドウが出ない | `--window` の位置が画面外 | `0 0 1024 600` に変える |

## 6. 設定ファイル

**既存の設定ファイルは1つも書き換えていません。戻す作業は不要です。**

シナリオが専用の設定を名指しする方式（`ConfigFile`）なので、普段の
`manual_drive.json` には触れていません。

| ファイル | 状態 |
|---|---|
| `config/manual_drive_realwheel_reverse.json` | **今回用に新規追加** |
| `config/manual_drive_realwheel_split.json` | 前回（順構成）用。無変更 |
| `config/manual_drive.json` | 無変更 |
| `config/virtual_driver.json` | 無変更 |

新規ファイルで既定から変えたキー:

| キー | 値 | なぜ |
|---|---|---|
| `input_type` | `sdl2_wheel` | 実機のペダル／ハンドルを使う |
| `override.enabled` | `true` | これが無いとペダルが効きません（最初のフレームから有効にするため） |
| `auto_resume_button` | **`3`** | **MANUAL→AUTO復帰用（Triangle/△、G29既定配置）。** これが無い（既定 -1）と
  台帳のボタンバス（`74814b61`）があってもハンドルのどのボタンも復帰を起こせません
  （`SDL2WheelInput::Poll` の `read_btn` は `btn_id>=0` のときしか
  `ButtonBits::AUTO_RESUME` を立てないため）。2026-07-30 に本キーを追加。 |
| `ffb.target_track_enabled` | **`true`** | **今回の本題。** AIの操舵を実物のハンドルで感じるため |
| `ffb.safety_max_saturation_seconds` | `2.0` | 強い力が2秒続いたら走行を止める |
| `ffb.safety_max_runtime_seconds` | `120.0` | 無人放置に対する上限 |
| `ffb.safety_saturation_ratio` | `0.95` | 上記の「強い力」の基準（→ 0.570 で発火） |

`config/backup_original/` に出荷時のコピーがあります。

### テレメトリの正しいキー名（UDP 48202 の生JSON）

`GT_VirtualDriverTelemetryJson.cpp` が実際に書き出すキーだけを載せる
（存在しないキーを `dict.get(key, 0)` で読むと無警告で `0` が返るため、
本番の値と「未計測」を区別できない——2026-07-30 の実機セッションで実際に
踏んだ）。

| キー | 意味 |
|---|---|
| `driver.steer` | 横の所有者が出している実現値の操舵指令 |
| `override.lateral` / `override.longitudinal` | 各ドメインが今MANUALか |
| `override.manual_transition` / `override.auto_transition` | その1フレームで切り替わったか（エッジ） |
| `override.resume_pressed` | AUTO_RESUMEボタンが押されたか。**既知の欠落**: 非積分側（今回の構成のVD）では常に`false`で凍る。詳細下記 |
| `ffb.commanded_force` / `ffb.sample_effective_force` | サーボが出している力 |
| `ffb.target_norm` / `ffb.position_error` | AIの指令舵角 / 追従誤差 |
| `ffb.target_active` | サーボが有効か |
| `ffb.gates.actual_norm` / `.residual` / `.effective_force` / `.block_reason` | 介入検出器の診断値。**既知の欠落**: 非積分側では常に`0`/`"none"`で凍る。詳細下記 |

`ffb.gates.target_track` や `ffb.gates.total` のようなキーは**存在しない**。

### 既知の制限（テレメトリ）— 診断フィールドが逆構成で凍る

`override.resume_pressed` と `ffb.gates.*` は、**この逆構成のようにVDが非積分側の
とき、常に初期値のまま（`resume_pressed=false`、`gates.*=0`/`"none"`）で凍ります。**
**機能そのものは動きます。** 死んでいるのは「なぜ発火した／しなかったかを後から
診断する」ためのテレメトリだけです。**未修正。**

**この2つが 0 のままでも「ボタンが効いていない」「検出器が動いていない」と読まないでください。**
帰属は `override.auto_transition` / `override.lateral` の遷移と `ffb.commanded_force` の値で見ます。

原因と、この欠落で実際に誤診しかけた記録は
[一次記録 §3](../measurements/realwheel_handover_results_2026-07.md) にあります。

## 7. 報告してほしいこと

- ハンドルを軽く触れただけのとき、進路が変わらなかったか
- ペダルで加減速できたか
- **カーブ途中で止めたとき、前輪の向きが保たれたか**（最重要）
- 再発進で車線から出なかったか
- ハンドルの動き方が「滑らかに追従」だったか、「振り切れる／振動する」だったか
- 手順7で、しっかり回すとオーバーライドが発火したか（ハンドルが自分の操作どおりに動いたか）
- （方法2で確認した場合）`driver.steer` の値がカーブ中に変化していたか
- 手順8で、Triangle（△）ボタンを押すとAIの操舵に戻ったか
- Triangleボタンを押していないのに AI の操舵に戻った場合はそれ自体を報告してください（想定外の動きです）

うまくいかなかった場合は、画面の様子と、PowerShell に出ているログの最後の20行を貼ってください。
