# AD 走行中の手介入検出 — しきい値の調整指針

対象: ハンドルコントローラ（フォースフィードバック付き）で AD 走行しているとき、
**運転者が手を出したことを検出して MANUAL に切り替える**機能のしきい値調整。

読者: 自分のハードウェアに合わせて検出感度を追い込みたい利用者。

> **この文書の位置づけ**: ここに書いてあるのは**利便性のための調整**である。
> **既定値の安全性は製品側の責任であり、調整できることを理由に利用者へ移すものではない。**
> 既定値は実機での受け入れ試験に合格した値であり、調整せずに使えることが前提。
> 調整は「自分のハードウェアに合わせてもっと良くしたい」利用者のための手段であって、
> 既定のままでは不十分だという意味ではない。

---

## 1. 何を見て検出しているか

検出器は**シャドウ**を持っている。シャドウとは「もし誰も触っていなければ、
サーボが押しているホイールは今どこにいるはずか」を、力とホイールの物理特性
（静止摩擦・力→速度・速度上限）から積分して求めた予測位置である。

```
residual = | 実測の軸位置 − シャドウの予測位置 |
```

`residual` が `residual_threshold` を超えた状態が `sustain_time` 続いたときに MANUAL へラッチする。

* 誰も触っていなければ、実測はシャドウの予測どおりに動くので `residual` は小さい。
* 人が握って邪魔をすると、実測だけが予測から外れるので `residual` が立つ。

**この方式の狙いは「AD が舵を切っている最中でも、内側で押さえる介入を拾える」ことにある。**
単純に「ホイールが動いた」で判定すると、AD が動かしている分と区別できない。

### 調整できるパラメータ

| キー | 既定 | 意味 |
| :--- | ---: | :--- |
| `ffb_target_track_override_residual_threshold` | 0.08 | ラッチ判定のしきい値 [axis-frac] |
| `ffb_target_track_override_sustain_time` | 0.10 | しきい値超えが続くべき時間 [s] |
| `ffb_target_track_override_residual_reanchor_tau` | 1.5 | シャドウのドリフトを実測へ引き戻す時定数 [s] |
| `ffb_target_track_override_shadow_onset_grace` | 0.05 | 動き出し直後の判定猶予 [s] |
| `ffb_target_track_override_shadow_breakaway`（`_left` / `_right`） | 0.21 / 0.170 / 0.190 | シャドウが使う静止摩擦 |
| `ffb_target_track_override_shadow_force_to_velocity` | 3.35 | 力→速度の傾き |
| `ffb_target_track_override_shadow_v_max` | 1.0 | 速度上限 [axis-frac/s] |
| `ffb_target_track_override_shadow_kinetic` | 0.16 | 動摩擦（力→速度の切片） |
| `ffb_target_track_override_shadow_dead_time` | 0.041 | ホイールの無駄時間 [s] |
| `ffb_target_track_override_shadow_velocity_tau` | 0.018 | ホイールの一次遅れ [s] |

`shadow_*` は**接続しているホイールの物理特性**なので、機種を替えたら測り直しが要る
（既定値は Logitech G29 の実測）。`residual_threshold` / `sustain_time` は
**感度の好み**であり、利用者が追い込む主対象である。

> **反映のタイミング**: これらの値は**走行の開始時に読まれる**。
> 走行中に変更しても、その走行には反映されない。**次の走行から効く。**
> C++ の再ビルドは不要。

## 2. 単位の換算（**まずここを押さえる**）

しきい値の単位は **axis-frac**（軸のフルスケール比、±1.0）。
ホイールの回転角に直すには回転範囲を掛ける。G29 は 900°（±450°）なので:

```
1.0 axis-frac = 450°
```

| しきい値 [axis-frac] | ホイール角 [°] |
| ---: | ---: |
| 0.01729 | 7.8（**物理的な検出下限**・後述） |
| 0.02 | 9.0 |
| 0.03 | 13.5 |
| 0.05 | 22.5 |
| **0.08（既定）** | **36.0** |
| 0.10 | 45.0 |

**他機種では回転範囲が違う**ので、この換算表はそのまま使えない。
自分のホイールの lock-to-lock 角度で割り直すこと。

## 3. しきい値を下げると何が起きるか

**拾える介入が小さくなる。同時に誤検知が増える。**

### 3-1. 拾える下限

しきい値を下げていっても、**0.01729 axis-frac（G29 で約 7.8°）より小さい介入は
原理的に検出できない。** これはしきい値ではなくハードウェアが決める床である。

根拠: サーボが出す力が静止摩擦を破れなければ、ホイールは押されても実測が動かず、
かつシャドウも動かないので `residual` が立たない。境界は

```
kp · x + friction_ff · tanh(x / eps) = shadow_breakaway
```

を満たす `x` で、出荷値（kp=4.0 / friction_ff=0.15 / eps=0.010 / breakaway=0.21）を
入れると **x = 0.01729 axis-frac** になる。これより軽い抵抗は、無負荷のホイールでも
動かないので**仕様として検出しない**。

したがって実効的な検出下限は

```
検出できる介入の大きさ ≈ max(0.01729, residual_threshold)
```

で、**しきい値を 0.01729 より下げても下限は下がらない**（誤検知だけが増える）。

### 3-2. 誤検知の側（実測）

手放し走行で `residual` がどこまで立つかが、しきい値の下限を決める。
2026-07-26 に実機 G29 で 12 走行（3 シナリオ × 4 セッション）を手放しで測った結果:

| 構成 | 走行数 | `residual` p95 | p99 | **最大** | 0.08 に対する余裕 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 出荷既定（操舵躍度上限 OFF） | 6 | 0.0091–0.0441 | 0.0208–0.0549 | **0.0566** | 1.41x |
| 操舵躍度上限 ON（25） | 6 | 0.0040–0.0211 | 0.0118–0.0452 | **0.0665** | 1.20x |

**全 12 走行で MANUAL ラッチ 0 件、`sustain_accum` は全走行で 0.000000**
（＝しきい値を一度も超えず、継続クロックが一度も回っていない）。

読み方:

* **出荷既定では、しきい値を 0.057 より下げると、今回の走行では誤ラッチしていた。**
* 躍度上限を ON にすると手放しの残差が上がるので、**しきい値の下げ代がさらに狭くなる**（0.067 まで）。
* p50 は 0.0001–0.0003 と極端に小さい。**平均は判断に使えない。最大で見ること。**

### 3-3. 走行ごとのばらつき（**下げるときに一番効く事実**）

**同一 config・同一シナリオ・同一ホイールでも、手放しの残差は走行ごとに大きく振れる。**

| 走行 | 1 回目の最大 | 2 回目の最大 |
| :--- | ---: | ---: |
| right_turn | 0.0377 | **0.0566**（+50%） |
| tljunction | 0.0386 | **0.0549**（+42%） |

一方で AD の指令側は決定的である（同じ 2 回で操舵指令の躍度 max は 288.264 と 288.265 で一致）。
**振れているのは物理ホイール側であって、指令側ではない。**

したがって:

> **1 回の走行で「余裕がある」と判断してしきい値を下げてはいけない。**
> 最低でも数回繰り返し、その**最悪値**を基準にすること。

## 4. しきい値を上げると何が起きるか

**誤検知は減る。代わりに、押さえる介入から順に拾えなくなる。**

拾えなくなる順序は「介入の弱い順」ではなく**介入の種類順**である点に注意する。
検出は `|実測 − シャドウ|` なので、

| 介入の種類 | しきい値上げの影響 |
| :--- | :--- |
| **内側で押さえる**（AD と同じ向きに、AD より手前で止める） | **最初に拾えなくなる**。実測とシャドウの差が構造的に小さいため |
| **センター保持**（AD が切ろうとするのを握って動かさない） | 次に拾えなくなる。AD の指令が大きくなるまで差が開かない |
| 追い越し（同じ向きに切りすぎる） | 差が開きやすいので比較的残る |
| 逆方向へ切る | 最も差が開くので最後まで残る |

**「内側で押さえる介入こそ最も自然」という前提で設計されている**ので、
しきい値を上げるのは**この機能の主目的を削る方向**である。
誤検知が出るからといって安易に上げず、まず §5 の手順で自分のハードの残差分布を測ること。

`sustain_time`（既定 0.10 s）を上げるのも同じ方向に効く。短い接触を落とす代わりに、
**とっさの介入の検出が遅れる**。手放しで `|実測 − 指令|` が 0.015 を超える連続区間は
実測で最長 0.25 s だったので、0.10 s は「手放しの揺らぎより長く、人が握る秒単位より短い」
位置に置いてある。

## 5. 自分のハードウェアで追い込む手順

1. **ホイールを繋ぎ、手を触れずに数回走らせる。** 代表的なシナリオを 3 種類程度
   （直進中心・右左折・交差点）。**1 回では決めない**（§3-3）。
2. GUI のライブ表示で、走行ごとに次の 2 つを記録する。**平均は使わない。**
   * `residual` の**最大値** — しきい値に対する接近率 `A = max(residual) / しきい値`
   * `sustain_accum` の**最大値** — 発火までの到達率 `R = max(sustain_accum) / sustain_time`
     （`R` は実際にしきい値を超えた走行でしか 0 を離れない）
3. **`A` の最大値が 0.7 前後に収まっているか**を見る。
   出荷既定 0.08 のもとで、G29 の実測は 6 走行で `A` = 0.31〜0.71 だった。
   しきい値を下げるということは、この `A` を全体に押し上げることに等しい。
   例: しきい値を 0.08 → 0.06 にすると、同じ走行の `A` は 0.31〜0.71 から 0.42〜0.94 になる。
4. その値で再び手放し走行を数回行い、**MANUAL ラッチが 0 件**かつ **`R` が 0 のまま**で
   あることを確認する。`R` が 0 を離れたら、そのしきい値では発火の一歩手前まで来ている。
5. 実際に握って介入し、**拾ってほしい大きさの介入が拾えるか**を確認する。
   拾えなければ §2 の換算表で「その介入は今のしきい値で拾える大きさか」を確認する。
   下限 0.01729 axis-frac を下回る介入は、しきい値を下げても拾えない。
6. 誤検知が残る場合は、しきい値を上げる前に **`shadow_*` が自分のホイールに合っているか**を疑う。
   既定値は G29 の実測なので、別機種では合っていない。

> 機種別の `shadow_*` を実測で求める自動較正は将来の機能である
> （要件: `test_results/f7_wheel_autocal_requirements.md`）。
> 現状は手動で config を編集する。

## 6. 操舵躍度上限（乗り味オプション）— 既定 OFF

`ad_steering_envelope_steer_jerk_max`（既定 **0.0 = 無効**）は、AD 指令の**操舵の躍度**に
上限をかける。狙いは「MANUAL から AUTO へ復帰した瞬間にハンドルが急に取られる」感覚の緩和である。

**効果（ヘッドレス実測・車線 1 本分ずらしてからの復帰）**:

| 量 | 0（既定） | 25 |
| :--- | ---: | ---: |
| 復帰直後の立ち上がりの躍度 | −245.9 /s² | **−25.0 /s²** |
| 復帰時間の増分 | — | +0.02〜+0.24 s |
| オーバーシュート | 0 | **なし** |

**代償（実機実測）**: 手放しの残差が上がり、**しきい値の下げ代が狭くなる**（§3-2）。
実機 3 走行すべてで低下した。しきい値への接近率の分布から誤ラッチ確率を見積もると、
**ON は OFF より 6〜40 倍悪い**（各 6 走行からの外挿。倍率の幅は仮定する分布族による —
Gumbel で 6.1 倍、正規で 39.4 倍）。**倍率そのものは頑健でないが、
どちらの族でも ON が悪いという向きは一致する。**

**この代償があるため既定は OFF である。**
乗り味を優先したい利用者は、config または GUI から `25.0` を設定して有効化できる。
有効化する場合は、**§5 の手順をやり直してしきい値を取り直すこと**
（躍度上限 ON の実測最大は 0.0665 で、OFF のときの 0.0566 より高い）。

`0` または負値で無効になり、躍度上限なしの挙動にビット単位で戻る。

## 7. 触ってはいけないもの

* **`residual_threshold` を「誤検知が出るから」という理由だけで上げない。**
  検出下限が上がり、**内側で押さえる介入から順に拾えなくなる**（§4）。
  まず `shadow_*` が自分のホイールに合っているかを疑う。
* **安全包絡線の上限**（`ad_steering_envelope_a_lat_max_steer` /
  `_yaw_rate_max` / `_steer_rate_max`）は 15 シナリオの実車計測から決めた**確定値**であり、
  乗り味の調整対象ではない。
* **`ffb_safety_max_saturation_seconds` / `ffb_safety_max_runtime_seconds`**（既定 0 = 無効）は
  **無人走行専用の歯止め**。対話利用で有効にすると走行が途中で止まる。
