## 1. ポリシーのコントローラ非依存性（設計書 §12 の残確認事項）

**結論: 非依存であることを実走で確認した。** `StopYieldSignAware` は ManualDrive の ego に対して STOP_AT_S 制約を出す。

| 実行 | 観測 |
| :--- | :--- |
| `md_sng_stop_sign`（stop_at_stop_sign=true） | `gt.acc.stop_requested=true` が t=6.9〜16.9 の 201 フレーム。ego は停止線手前で v→0 |

この確認が必要だったのは「`ITrafficPolicy` の契約に適合するか」ではない。
両ポリシーは `RouteSignalScan::ScanSignalsAhead` を通じて **ego の Position から前方を歩いて**標識を探すが、その歩行は `pos.CopyRoute(ego->pos_)` で ego の Route を複製するところから始まる。
ManualDrive の ego は Route を**持たない**（人間が行き先を決めるので経路計画がない）。
未確認だったのは「Route が無いとき、この歩行が何か見つけるのか」であって、インタフェース適合ではなかった。
`MoveAlongS(step, 0.0, 0.0, true, HEADING_DIRECTION, true)` は Route が無ければ straight-most で進むため、直線路では前方の標識に到達する——それが実測で裏づけられた。

**射程の限定（誇張しないために明記する）**: 確認したのは `StopYieldSignAware` × 直線路 1 本である。
`TrafficLightAware` 本体と、分岐のある道路（Route があれば経路側を選ぶが、無ければ straight-most で「たまたま」選ばれた接続路を見る）での挙動は本実測の射程外。
交差点で ManualDrive の Stop&Go を使う構成を作るときは、**そこで再度実測する**こと。

## 2. クリープと停止保持

### 2-1. 最初の実行で停止保持が一度も成立しなかった（閾値が構造的に到達不能だった）

`stop_speed_eps_mps` の当初値 **0.10 m/s** で `md_sng_lead_stop_restart` を回すと、**`gt.acc.stop_hold` が 640 フレーム中 0 フレーム**だった。
ego の最低速度は **0.158 m/s** で、閾値を下回らない。

原因は RealVehicle の AT クリープである。
ブレーキを当てない限り車両は 0 に収束せず、**クリープ速度 ≈0.16 m/s に収束する**。
`stop_speed_eps_mps` をこの床より下に置くと、「停止した」と判定される瞬間が**原理的に来ない**。

この失敗様式が厄介なのは、上流が全部正しく見えることである——ACC は ACTIVE、実効上限は 0 まで減衰、車両は目視では止まっている、それでも `gt.acc.stop_hold` は永久に false のまま。
「保持ブレーキ量が足りない」でも「判定が厳しすぎる」でもなく、**判定の入口に到達できない**。
既定値を **0.5 m/s（1.8 km/h）** に引き上げて解消した。

> **恒久ルール**: `stop_speed_eps_mps` を再校正するときは、先にクリープ床を測ること。床より小さい値は Stop&Go を丸ごと死んだコードにする。

### 2-2. 保持ブレーキ量の実測

`hold_brake = 0.30`、`stop_speed_eps_mps = 0.5` で再実行した結果（連続する保持区間ごとの最大変位）。

| 実行 | 保持区間 | フレーム数 | 保持中の最大変位 |
| :--- | :--- | ---: | ---: |
| `md_sng_lead_stop_restart` | 17.70–20.90 s | 65 | **0.017 m** |
| 同（再発進後の2度目の保持） | 22.40–34.00 s | 233 | **0.032 m** |
| `md_sng_stop_sign` | 15.35–34.00 s | 374 | **0.015 m** |

18.7 秒保持して 0.015 m。クリープは完全に抑止されている。
変位は位置ノイズの水準であって「ゆっくり転がっている」のではない（転がっていれば時間に比例して伸びるが、11.6 秒保持と 18.7 秒保持で変位が増えていない）。

**`hold_brake = 0.30` を採用値として確定する。**
matcher `stop_hold_stationary` の `max_displacement_m` は既定 0.5 m で、実測 0.032 m に対して 15 倍の余裕がある——この余裕は意図的で、閾値を実測ぎりぎりに置くと物理の微小変更で赤くなる警報疲れの側に倒れる。

### 2-3. 再発進（段a）

アクセルパルス（t=21.0、throttle 0.35）で保持は **t=20.95 に解除**され、ego は **2.43 m/s** まで加速した。
解除が 21.00 でなく 20.95 なのは、プロファイルの線形補間が t=20.9 の 0.0 から t=21.0 の 0.35 へ向かう途中、20.95 で 0.175 に達して `restart_accel_threshold=0.10` を超えるためである（仕様どおり）。

**「飛び出し」は観測されなかった**。解除後の加速は 2.43 m/s までで、これはパルスのスロットル 0.35 に対する素直な応答である。設計書 §12 が懸念した「保持ブレーキを抜いた瞬間の飛び出し」は、この保持量では起きない。

### 2-4. 副産物: プロファイルのパルス時刻も実測で決めた

最初の probe ではパルスを t=16.0 に置いていたが、そのとき ego はまだ **1.2 m/s で転がっていた**（停止に至っていない）。
つまりそのシナリオは「Stop&Go の解除」ではなく「アクセル一時上書き」を測っていた——実行は成功し、フレームも出て、report も出るが、**主張していることと測っていることが違う**。
`acc_ops_stop_restart.json` のパルスを t=21.0 に移した。プロファイルの description にも実測由来であることを書いてある。

## 3. この実測が閾値に与えた影響（まとめ）

| 値 | 実測前 | 実測後 | 根拠 |
| :--- | :--- | :--- | :--- |
| `adas_acc_stop_speed_eps_mps` | 0.10 | **0.5** | クリープ床 0.16 m/s より上でなければ保持が成立しない |
| `adas_acc_hold_brake` | 0.30（推測） | **0.30（確定）** | 18.7 s 保持で変位 0.015 m |
| `acc_ops_stop_restart` のパルス時刻 | 16.0 s | **21.0 s** | 16.0 では停止前でアクセル上書きを測ってしまう |

いずれも「閾値を動かして緑にした」のではなく、**実測してから閾値を置いた**。
動かしたのは幾何・タイミング・入力プロファイルと、到達不能だった 1 つの既定値である。
