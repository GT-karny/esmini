## junctions.common.not_only_two  [PARTIAL_DETERMINISTIC]
CHECK_LOGIC: For every <junction> where @type is absent or @type="default": (1) roads = union of connection/@incomingRoad and connection/@connectingRoad across its <connection> children; (2) if len(roads) != 2, no finding; (3) if len(roads) == 2: exempt (no finding) if this junction's @id appears in any /OpenDRIVE/junctionGroup/junctionReference/@junction in the document, OR if the junction has >=1 <crossPath> child; otherwise flag as an advisory ("should"-level) finding: a common junction connecting exactly two roads with no documented structural justification. @type="direct" and @type="virtual" junctions are excluded from this rule entirely (separate Annex F sub-namespaces govern them, and 2-road direct junctions -- e.g. motorway on/off-ramps -- are their canonical, expected shape).
DO_NOT_IMPLEMENT (ambiguous residual, leave uncovered): The exemption list (junctionGroup membership, crossPath-hosting) is not declared exhaustive by the spec text; other legitimate reasons for a 2-road common junction (e.g. hosting other junction-only features such as elevationGrid/boundary, or a deliberate lane-count/width transition needing laneLink flexibility a plain road link can't express) are conceivable and not enumerated, so a flag under this refined test is still only a candidate for human review, not a guaranteed violation.
SPEC_EVIDENCE: Annex F.4.5.3 (map_rules.html, UID asam.net:xodr:1.9.0:junctions.common.not_only_two): "Junctions should not be used when only two roads meet." Same bullet repeated verbatim in 12_02_common_junctions.html's "Rules" list for common (type=default) junctions -- the rule is not repeated in 12_06_direct_junctions.html or 12_07_virtual_junctions.html, whose own Annex F sub-namespaces are junctions.direc
