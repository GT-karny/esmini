## road.railroad.rail_lane_width_validity  [PARTIAL_DETERMINISTIC]
CHECK_LOGIC: For every <lane> with @type in {"rail","tram"} inside every road/lanes/laneSection/{left,center,right} group, for each of its <width> child elements read @a (the width value at that segment's local ds=0). Flag a violation if float(@a) <= 0 for any such width segment belonging to a rail/tram lane. Rationale: a real rail-bound vehicle necessarily has strictly positive width, so a rail/tram lane whose authored width touches zero or goes negative at a segment start can never satisfy 'at least the width of rail-bound vehicles,' regardless of what the (spec-unspecified) vehicle-width constant actually equals -- this is provable without needing that missing numeric threshold. (A stricter variant would also sample a+b*ds+c*ds^2+d*ds^3 across each segment's [0, next-sOffset) span to catch a mid-segment dip below zero, but the ds=0 check alone already recovers the clear-cut degenerate case using pure attribute reads, no geometry/network context needed.) Grounded against GT_esmini/test/odr_fixtures/official/examples/Ex_Railway-Station/Ex_Railway-Station.xodr: both tram lanes have @a=2.5, correctly non-violating.
DO_NOT_IMPLEMENT (ambiguous residual, leave uncovered): The actual normative threshold -- 'the width of rail-bound vehicles' -- is never given a numeric value anywhere in the OpenDRIVE 1.9 spec (no reference vehicle width, no cited standard), and real rail/tram vehicle widths vary substantially (fixture evidence: Ex_Railway-Station.xodr uses a=2.5 for tram; prior investigation independently found ~2.5m tram vs ~3.5m heavy-rail in the corpus). Above the provable 'non-positive is definitely too narrow' floor, choosing any specific positive cutoff is an unresolvable external-knowledge/judgment call the spec does not make -- including the disputing auditor's own suggested '~1.435m standard gauge' proxy, which additionally conflates rail *gauge* (the distance between the two rails) with vehicle *width* (a different physical quantity entirely), so it should not be adopted even as a heuristic.
SPEC_EVIDENCE: Annex F.6.17.2, UID asam.net:xodr:1.7.0:road.railroad.rail_lane_width_validity: "The width of the lane shall be at least the width rail-bound vehicles." (verbatim, grammatically missing 'of'; no numeric value for rail-bound-vehicle width is given anywhere in the OpenDRIVE 1.9 spec).
