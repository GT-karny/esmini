## road.lane.lane_reverse_left_right  [PARTIAL_DETERMINISTIC]
CHECK_LOGIC: For each <road>/<lanes>/<laneSection>: collect left_driving = <left>/<lane> elements with @type='driving' (empty list if no <left>), and right_driving = <right>/<lane> elements with @type='driving' (empty list if no <right>). Only evaluate laneSections where BOTH left_driving and right_driving are non-empty (a laneSection with driving lanes on only one side has no RHT/LHT counterpart to swap against and is out of scope). For such two-sided laneSections, flag a violation if EVERY lane in left_driving UNION right_driving has @direction == 'reversed' (attribute present and literally 'reversed'; absent or 'standard' or 'both' does not count). This is independent of the road's own @rule value -- the equivalence holds symmetrically in both directions per the 11.3.1 formulas. No geometry is needed; only <road>, <lanes>/<laneSection>/<left|right>/<lane>@type, and <lane>@direction are read.
DO_NOT_IMPLEMENT (ambiguous residual, leave uncovered): The check only catches the airtight 100%-both-sides-reversed signature. Any partial or mixed reversal (some but not all driving lanes reversed, or reversal confined to one side only) is structurally indistinguishable between 'legitimate single/multi-lane contraflow' (the sanctioned use of @direction=reversed, per 11.3.1's own phrasing and the one real fixture found) and 'a sloppy/partial attempt to fake a hand-of-traffic change' -- the spec supplies no threshold or additional attribute to arbitrate that residual space, so it remains a genuine authorial-intent judgment call outside the deterministic sub-case.
