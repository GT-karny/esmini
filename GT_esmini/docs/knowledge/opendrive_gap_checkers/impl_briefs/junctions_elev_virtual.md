# Implementation brief: add these rules to check_junctions_elev_virtual.py

## junctions.virtual.main_road_only  [PARTIAL_DETERMINISTIC]
CHECK_LOGIC: For every <junction @type="virtual">: (1) referential integrity -- @mainRoad must equal the @id of some <road> element in the document; flag if not found. (2) participation -- flag if NEITHER holds: (a) some <connection>/@incomingRoad == @mainRoad, or (b) some <connection>/@connectingRoad resolves to a <road id=connectingRoad> whose own <link><predecessor|successor elementType="road"> has @elementId == @mainRoad. Both checks are pure XML/attribute lookups requiring no coordinate geometry.
DO_NOT_IMPLEMENT (ambiguous residual, leave uncovered): The rule's exclusivity clause -- that the junction is used for branches off the main road ONLY, i.e. that every other road drawn into the junction (such as an intermediate road like "99" in the spec's own parking-lot example, which is itself neither @mainRoad nor directly link-referencing it) is a legitimate branch/sub-branch of that main road rather than an unrelated through-road that should have used a common junction instead -- requires judging real-world road classification and topological intent (driveway/parking spur vs. genuine intersecting street), which the spec itself flags as a distinct concern ("Virtual junctions shall not replace common junctions and crossings that connect multiple roads") but does not reduce to any link-graph or attribute test. The second sentence ("The main road has priority if not specified otherwise") is default run-time semantics for a consuming simulator, not an authoring constraint, so nothing about it is checkable in the XML at all.
